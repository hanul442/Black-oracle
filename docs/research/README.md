# BLACK ORACLE Research & Development

This directory is the evidence-backed R&D knowledge base for BLACK ORACLE.

## Operating loop

`Research → Review → Hypothesis → Experiment → Result → ADOPT / REJECT / REVISIT`

Research is not an implementation mandate. Production/Paper trading behavior must not change solely because an external source looks promising. A candidate must be linked to an explicit hypothesis, validation protocol, metrics, and result.

## Domains

- `design/` — financial UX, visualization, mobile interaction, accessibility
- `quant/` — signals, portfolio construction, regime logic, execution and validation
- `ai-ml/` — model/strategy routing, factor discovery, agents and explainability
- `data-infrastructure/` — canonical instruments, lineage, quality and reproducibility
- `product-competitor/` — financial workspaces, automated-trading products and workflow patterns
- `evidence-validation/` — statistical robustness, implementation risk and experiment governance
- `research-ledger/` — auditable status and experiment lineage

## Status vocabulary

`DISCOVERED` → `REVIEWED` → `TEST` → `ADOPT` / `REJECT` / `REVISIT`

`REFERENCE` is for useful design/methodological precedent that does not itself warrant an experiment.

## Evidence quality

- **A** — primary paper with reproducible method/code/data, official technical documentation, or strong institutional primary source.
- **B** — primary research with meaningful empirical evidence but material external-validity/reproducibility limits.
- **C** — practitioner/design reference useful for hypotheses or patterns, not evidence of investment performance.

## Required research record

Every substantive entry should record source/date, evidence grade, BO relevance, current gap, hypothesis (when testable), experiment, success/failure metrics, status, and implementation boundary.
