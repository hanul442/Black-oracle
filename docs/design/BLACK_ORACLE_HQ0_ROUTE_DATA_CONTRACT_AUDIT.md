Status: HQ-0 COMPLETE / IMPLEMENTATION CONTRACT CANDIDATE

Branch: `design/hq-office-os-v1`  
Production impact: None

## 1. Executive finding

HQ can be built without replacing the existing trading system, but the current application has one major UX/architecture constraint:

> **The production mobile UI is state-routed inside one React component, not URL/deep-link routed.**

The current production mobile entry is:

`src/main.tsx → ResponsiveRoot.tsx → src/mobile/BlackOracleMobileApp.tsx → BlackOracleMobileAppV11_1.tsx`

The wrapper confirms V11.1 is the current mobile surface and adds source-health monitoring for:
- `/api/trading-status`
- `/api/strategy-factory-status`
- `/api/events`

The inner V11.1 UI uses local React state for:
- `command`
- `markets`
- `oracle`
- `trade`
- `lab`
- `system`

Instrument Cockpit and detail views are overlays driven by `market` and `detail` state.

Therefore HQ can navigate into current views immediately through an internal navigation adapter, but **shareable/restorable URL deep links do not yet exist**.

This is the primary HQ-0 bottleneck.

This preserves non-fabrication.

## 3. Current authoritative read surfaces

| Need | Current source | Current UI use | HQ use |
|---|---|---|---|
| Runtime / PAPER portfolio | `GET /api/trading-status` | V11.1 loads every 30s | Portfolio Wall, Trading Floor, risk/health summary |
| Canonical event tape | `GET /api/events?limit=500` | V11.1 loads every 30s | Agent movement, activity ribbon, room state |
| Strategy Factory | `GET /api/strategy-factory-status` | Lab | Model Validation / Incubator |
| Market master/chart | `GET /api/market-chart` | Markets + chart | Instrument bridge |
| Instrument canonical lineage | `GET /api/instrument-cockpit?market=...` | Endpoint exists; V11.1 currently derives cockpit locally | Target source for HQ instrument deep drill |
| Decision Replay | `GET /api/decision-replay?traceId=...` | Endpoint exists; V11.1 currently renders replay from in-memory event projection | Target authoritative replay bridge |
| Paper runtime routes | `/api/trading/*` Express routes | lower-level operational API | Not directly polled by HQ |
| Full Report | none found in main tree | unavailable | BLOCKED / PLANNED |

### Important consolidation finding

There are currently two patterns for Instrument/Replay:
1. dedicated canonical server endpoints already exist;
2. V11.1 also derives these views locally from `trading-status + events`.

HQ should **not create a third lineage implementation**.

Recommended direction:
- office-level lightweight state from `trading-status + events`
- deep instrument inspection progressively moves to `/api/instrument-cockpit`
- trace-specific replay uses `/api/decision-replay`

`HqNavigationTarget` supports:
- `CURRENT_VIEW`
- `INSTRUMENT`
- `DECISION_REPLAY`
- `TRADE`
- `REPORT`
- `EVENT`

### Current adapter behavior

#### Portfolio Wall
→ `CURRENT_VIEW: trade`

#### Strategy Lab / Model Validation
→ `CURRENT_VIEW: lab`

#### Instrument event
→ `INSTRUMENT: market`

#### Council / Risk event with canonical trace ID
→ `DECISION_REPLAY: traceId`

#### Trade / Order / Outcome
→ `TRADE: tradeId/market`

#### Report Board
→ `REPORT: PLANNED` until the product plane exists

## 8. Deep-link gap

### Current limitation

Refreshing the page loses:
- selected view
- open Instrument Cockpit
- detail sheet
- trace context

This is acceptable for existing local navigation but weak for HQ because rooms/events should be able to point to durable work objects.

### HQ-1/HQ-3 requirement

Introduce a thin navigation state adapter before financial bridges are considered complete.

Candidate URL vocabulary:

- `?surface=hq`
- `?surface=instrument&market=KRX-005930`
- `?surface=decision&traceId=...`
- `?surface=autotrade&panel=positions`
- `?surface=trade&tradeId=...`
- `?surface=lab`
- future: `?surface=report&reportId=...`

This URL contract is **not wired in HQ-0** and must not be documented as deployed.

## 9. Financial bridge acceptance contract

HQ is not allowed to ship as the primary Home surface until all of these are true:

1. Trading Floor data is sourced from canonical existing read models.
2. Portfolio/Position values are never generated by the animation layer.
3. A position terminal resolves to the same market/position shown by AutoTrade.
4. Council/Red Team/Risk visuals preserve the same trace identity used by Decision Replay.
5. Critical runtime/risk alerts are visible without panning to the affected room.
6. Report Board shows PLANNED when the Report product is unavailable.
7. HQ event movement can be explained by a canonical source event ID.
8. No HQ event becomes execution authority.
9. Camera/animation state is never persisted as financial truth.
10. Existing V11.1 Trade/Lab/System access remains reachable while HQ rolls out.

## 11. HQ-0 decision

**Proceed.**

The existing repository is already strong enough to support the office as a projection layer because the canonical event tape and PAPER read model exist.

The main architectural corrections required before visual implementation are:

1. **do not duplicate canonical lineage in the HQ layer;**
2. **introduce durable navigation/deep-link state;**
3. **treat Report as unavailable until it exists in runtime code;**
4. **use canonical events as the cause of agent motion;**
5. **keep the office read-only with respect to investment authority.**

HQ-0 is therefore complete as a contract/audit stage. The next implementation slice is **HQ-1A navigation adapter**, followed by the static 2D shell.
